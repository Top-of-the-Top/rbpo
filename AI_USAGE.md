# Использование генеративного ИИ

Команда использует генеративный ИИ при подготовке проектных документов. В данном документ полностью описывает, как команда использует ИИ в рамках проекта. 

## Инфраструктура ИИ

Раздел описывает инфраструктуру ИИ в проекте: модель, управление контекстом, скиллы и другие инструменты.

- **Инструмент**: Claude Code (CLI-агент Anthropic) с моделями Claude Code и Claude Opus.
- **Контекст сессии (`CLAUDE.md`)**: контекст агента задается файлом `CLAUDE.md`, в котором описан контекст проекта - название, тема, все правила по написанию кода.
В файле описывается вся необходимая информация для агента, которая позволяет ИИ быстро ориентироваться в проекте, понимать архитектуру, принципиы, фреймворки и другие особенности проекта. Файл написан на английском языке для экономии токенов.
- **Скиллы (`.claude/skills`)**: в в данной директории содержаться скиллы - навыки агента, которые позволяют декларативно описать решение повторяющеся зщадачи. Например, это может быть создание тикета, репорт об использовании ИИ и многое другое. Данные навыки ускоряют разработку и позволяют агенту экономить токены на лишних объяснениях - агент для решения повторяющейся задачи использует определенный скилл.
- **Настройки (`.claude/settings.json`)**: здесь содержаться общие настройки Claude Code в проекте, а также хуки. `Хук` позволяет триггерить действие или скилл при решении определенной задачи, чтобы агент не забыл выполнить обязательную проверку или репорт. Например, в проекте есть хук `PostToolUse`, который требует докладывать об использовании ИИ и записывать любое использование агента в файл `AI_USAGE.md` в формате, который описан в курсе.

## Использование ИИ в задачах 
Ниже зафиксированы задачи, в которых применение повлияло на содержание материалов проекта, и выполненная проверка.

### Уточнение паспорта проекта

- Участник: M3
- Задача: уточнить описание продукта, границу, роли и сквозные сценарии в `PROJECT.md`
- Использование ИИ: работа велась в Claude Code с использованием подготовленных сценариев работы (скиллов) над документами; предложены формулировки границы продукта, таблицы ролей и описаний сценариев, а также вариант подачи интерфейса в виде доски со статусами
- В проект вошло: уточнённые разделы 1 по 9 паспорта, включая описание доски, приёмки результата автором и заполненный раздел о стеке
- Проверка человеком: команда перечитала паспорт, сверила роли и разграничение действий с замыслом продукта и темой задания, проверила соответствие сценариев выбранной границе, исправила формулировки
- Связанный результат: `PROJECT.md`

### Подготовка требований безопасности

- Участник: M3
- Задача: сформулировать требования безопасности `SR-01` по `SR-09` с критериями приёмки к семинару S02

- Проверка человеком: команда проверила каждое требование на соответствие своему продукту, обоснованность защитного свойства, отсутствие повторов и наличие наблюдаемого критерия приёмки; формулировки доведены до собственных
- Связанный результат: `SECURITY_REQUIREMENTS.md`, требования `SR-01` по `SR-09`

### Сравнительный анализ платформ управления задачами

- Участник: E95
- Задача: выяснить, какие функции есть у ведущих платформ управления задачами, и на этой основе определить базовое функциональное ядро продукта — что трекер задач должен уметь как минимум
- Использование ИИ: анализ выполнен с помощью ИИ-инструмента Dia; ИИ подготовил сравнительную матрицу из 8 платформ (ClickUp, Asana, Trello, Monday.com, Jira, Notion, Todoist, Microsoft To Do) и 52 функциональных признаков в 8 категориях (управление задачами, представления, совместная работа, автоматизация и ИИ, отчётность, интеграции, администрирование и безопасность, платформа и цены) по шкале «есть полностью / частично или только в платном тарифе / отсутствует»; источниками названы официальные страницы тарифов и документация вендоров, агрегаторы сравнений и отраслевые отчёты; ИИ также выделил 20 признаков, присутствующих повсеместно, рассчитал индекс покрытия функционала по платформам и составил профили платформ и рекомендации
- В проект вошло: сам отчёт (дата подготовки — 19 сентября 2026) в репозиторий не включён; его результат отражён в `PROJECT.md`, §4.1.4 (признаки категорий 1–3, число платформ с полной реализацией, решение по каждому признаку); использованы только категории 1–3 (управление задачами, представления, совместная работа) и порог «полностью реализовано минимум у 5 из 8 платформ» — по ним определён состав use case'ов; категории 4–8 в проект не вошли, рекомендации отчёта по выбору платформы и данные о ценах не использовались
- Проверка человеком: сверил отметки платформ с источниками; проверил выбор конкурентов и признаков; прочитал итоговый отчёт
- Связанный результат: `PROJECT.md` (раздел 4.1.4)

### Отбор базового функционала и описание use case'ов

- Участник: E95
- Задача: по результатам сравнительного анализа платформ определить базовый функционал и описать варианты использования в `PROJECT.md`
- Использование ИИ: в Claude Code по отчёту анализа посчитано, у скольких из 8 платформ признаки категорий 1–3 реализованы полностью (порог 5 из 8), предложен состав use case'ов, их структура (актор, предусловия, основной и альтернативные сценарии, постусловия), матрица прав и допустимых переходов статуса, схема аутентификации (логин, почта, пароль и одноразовый код), а также правила для комментариев, вложений, повторяющихся задач и обновления в реальном времени
- В проект вошло: раздел 4.1 паспорта — 28 use case'ов, общие правила, матрицы прав и переходов, трассировка «признак анализа → use case» с причинами отказа; из предложенного отсеяны шаблоны задач, гостевой доступ, Гант, спринты и эпики, а также модель данных, детали API, числовые параметры и ссылки на SR; часть решений оформлена как допущения (§4.1.5) и ожидает подтверждения команды
- Проверка человеком: прочитал и сверил состав признаков с анализом; вручную отсеял признаки, не входящие в границу; потребовал сократить избыточные детали и привёл use case'ы к классической форме; добавил отдельный логин и вход с одноразовым кодом; прочитал итоговый `PROJECT.md`
- Связанный результат: `PROJECT.md` (раздел 4.1)

Черновики документов подготовлены с использованием ИИ, содержательная проверка и фиксация изменений в репозитории выполняются участниками команды самостоятельно. Ответственность за включённый в проект результат несёт команда.
